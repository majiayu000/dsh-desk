# 跨设备查看、审批与继续任务 RFC

> 状态：Phase A 基础骨架已实现；PWA、E2EE 协议和不可信密文中继已有自动化测试，但尚未接入真实 Harness 会话，也未部署生产云中继。Phase B/C 继续受本文门禁约束。

## 1. 目标

电脑继续拥有并运行 Agent，手机只能在桌面明确授权的范围内：

1. 查看任务状态和经过最小化处理的事件；
2. 审批或拒绝一个具体工具调用；
3. 向同一会话补充指令；
4. 撤销手机设备，立即终止后续访问。

手机不能读取模型 API Key、任意浏览工作区、扩大桌面权限、创建未绑定的命令调用，或在桌面离线后代替桌面执行 Agent。

## 2. 信任模型

```text
手机/PWA ──端到端加密消息── 中继（只见密文） ──端到端加密消息── DSH Desk
                                                               │
                                                               ▼
                                                    本地 Harness / 工具审批
```

- **桌面是唯一权限真源**：Harness 的当前会话、工具请求和 permission preset 决定一个动作是否仍可审批。
- **中继不可信**：中继可以丢包、延迟、重复或排序消息，但不能读取内容、伪造有效签名或获得 API Key。
- **手机是可撤销设备**：每台手机拥有独立设备密钥和 scope；丢失一台设备不要求更换模型凭证。
- **上游业务状态不复制**：桌面桥接器只投影最小事件，不在云端建立第二套会话数据库。

## 3. 配对

1. 用户在本地 DSH Desk 主动点击“添加移动设备”。
2. 桌面生成一次性配对会话、临时公钥、128 位以上随机 nonce 和 2 分钟有效期。
3. 二维码只包含中继地址、配对 ID、桌面临时公钥和 nonce，不包含 API Key、会话数据或长期密钥。
4. 手机生成设备密钥，在二维码信道外通过中继完成带 nonce 的密钥确认。
5. 桌面显示设备名称、公钥指纹和将授予的 scope，用户必须在桌面再次确认。
6. 双方派生会话密钥；中继只保存密文信封和最短必要路由元数据。

配对码过期、被使用一次、桌面取消或连续失败后立即失效。不能用固定 PIN、邮箱链接或未经桌面确认的“自动发现”替代。

## 4. Scope

scope 分开授予，默认只有 `task:read`：

| Scope | 能力 | 默认 |
|---|---|---|
| `task:read` | 会话标题替代 ID、状态、阶段、非敏感进度 | 开启 |
| `approval:respond` | 对一个已存在、仍待处理的工具请求同意/拒绝 | 关闭 |
| `instruction:append` | 向一个已授权会话追加用户文本 | 关闭 |
| `notification:receive` | 接收状态和审批通知 | 开启 |

不存在 `workspace:read-all`、`credential:read`、`shell:execute` 或“管理员”scope。远程补充指令不能绕过 Harness 自己的工具审批。

## 5. 审批消息必须绑定的字段

每个审批请求包含并签名：

```text
protocol_version
desktop_id
device_id
session_id
tool_call_id
tool_name
canonical_arguments_hash
permission_snapshot_hash
request_nonce
created_at
expires_at
sequence
```

手机返回的同意必须覆盖同一组字段和 `decision=approve|deny`。桌面收到后依次检查：

1. 协议版本和设备 scope；
2. 设备未撤销、签名有效；
3. `expires_at` 未过期，时钟偏差在允许范围；
4. nonce 和 sequence 未使用，拒绝重放和倒序覆盖；
5. 当前待审批请求的参数哈希仍然相同；
6. permission preset 没有在请求后收紧；
7. Harness 仍处于同一待审批状态。

任何字段不一致都按拒绝处理。审批是单次、短时、精确工具调用授权，不能转化为本会话后续自动批准。

## 6. 数据最小化

默认手机状态页只展示：

- 用户可修改的设备内会话别名；
- 运行/等待审批/完成/失败状态；
- 开始时间、耗时和稳定错误码；
- 工具名称、参数类型和经策略允许的摘要。

默认不发送：

- API Key、Authorization header、Cookie；
- 完整提示词、模型响应和工具输出；
- 文件内容、完整路径、用户名、主机名；
- 环境变量、SSH/Git 私有地址；
- 未经逐项允许的工具参数。

“查看完整对话”不能作为第一版顺带开启的能力，必须单独设计内容过滤、删除和保留策略。

## 7. 撤销与恢复

- 桌面可以逐设备撤销；撤销更新本地列表并向中继写入不含内容的 tombstone。
- 被撤销设备的所有未处理消息失效，旧密钥不能重新配对。
- 桌面重新安装或选择“重置配对”后生成新的 desktop identity。
- 中继不可用时，桌面核心功能、任务执行和本地审批完全不受影响。
- 手机不能通过离线队列提交过期批准；恢复连接后必须重新获取当前请求。

## 8. 分阶段实现

### Phase A：只读验证

- 20 名长任务用户候补名单；
- 手机/PWA 只显示状态和通知；
- 不发送提示词、工具参数，不支持审批或补充指令；
- 每周使用两次以上的用户达到 30% 才进入 Phase B。

当前仓库中的 Phase A 骨架包括：

- `companion.html`：可安装 PWA，只渲染最小任务状态；
- `src/cross-device/protocol.ts`：P-256 ECDH、HKDF-SHA-256、AES-256-GCM、短时信封和重放序列；
- `relay/server.mjs`：内存型参考中继，只接受固定结构密文，读、写和一次性配对 capability 分离；
- `pnpm test:cross-device`：篡改、重放、过期、明文字段与 capability 越权测试；
- `pnpm relay:dev` + `pnpm companion:demo`：本地端到端演示，不代表生产部署。

PWA 把 capability 和不可导出的 `CryptoKey` 存在 IndexedDB，不使用 `localStorage`。配对载荷放在 URL fragment 中，浏览器不会把 fragment 发送给 Web 服务器。由于 Phase A 仍是纯 Web 客户端，XSS 仍能以当前页面身份发请求；因此页面使用严格 CSP、零第三方脚本，生产部署还必须配置 HTTPS、精确 CORS、速率限制、持久化 TTL、密钥撤销和安全响应头。

### Phase B：精确审批

- 只支持 Harness 已产生的待审批工具调用；
- 请求哈希、短时过期、nonce、sequence、签名和本地审计全部通过测试；
- 高风险命令可设置为“必须回到桌面确认”，手机端不能覆盖。

### Phase C：继续任务

- 单独授予 `instruction:append`；
- 明确显示目标会话和桌面设备；
- 新指令进入 Harness 正常权限流程，不能直接变成 shell/API 调用。

## 9. 必须通过的安全测试

- 伪造、篡改、过期、重复、乱序和跨会话审批全部被拒绝；
- 工具参数在请求后变化，旧批准失效；
- 桌面收紧 permission preset 后，旧批准失效；
- 被撤销设备、复制二维码、重复配对和中继重放不能恢复访问；
- 中继数据库泄露不能解密任务内容；
- 中继完全离线时桌面仍可本地工作；
- 手机 scope 不能通过消息字段或版本降级扩大；
- 日志和崩溃报告不包含明文消息、密钥和工具参数。

## 10. 需要确定的基础设施选择

### 方案 A：端到端加密云中继（推荐产品路线）

优点：手机离开同一 Wi-Fi 后仍可用，通知和离线短队列可控。代价：需要运营中继、推送、滥用防护、隐私政策、密钥轮换和可用性。

### 方案 B：仅局域网直连

优点：没有云端业务数据，原型简单。代价：跨网络不可用，路由器/防火墙复杂，直接暴露桌面监听面；仍必须做完整配对和加密，不能靠“同一 Wi-Fi”当认证。

### 方案 C：用户自托管中继

优点：高级用户拥有基础设施。代价：首次使用门槛高、推送困难、支持矩阵大，不适合作为默认增长功能。

已选择 **A，移动端先用可安装 PWA**，把中继限制为不可信密文邮箱；稳定后再决定是否做原生 App。仓库中的参考中继默认只监听 `127.0.0.1`，不会让 DSH Desk 或 Harness 对局域网/公网开放入站端口。生产云账号、域名和持久化服务仍需单独选择与部署。
