# DSH Desk 30 天执行计划

目标不是追 Star，而是证明“无需 Node 的可信发行 + 快速跟随官方”能让用户完成并持续使用 DSH。

## 第 1 周：发布可信度

- 准备 Apple Developer ID、App Store Connect API Key 和 Windows Authenticode 证书；
- 首次运行三平台 CI，修复真实平台差异；
- 在干净系统用户上验证无 Node 安装、启动、退出、卸载；
- 发布 macOS 签名/公证候选版，记录签名与 Gatekeeper 证据；
- 招募 5 名第一次使用 DSH 的测试者。

完成门槛：macOS 安装成功率 ≥95%，没有残留 Node/端口，所有失败有稳定错误码。

## 第 2 周：首次任务与兼容

- 观察 5 名新用户完成模型配置和首次任务；
- 记录中位耗时、失败点和看文档次数；
- 让每日 latest 候选工作流产生第一份公开记录；
- 建立 Desktop/DSH/Node 兼容更新 PR 模板；
- 制作真实 20–30 秒首次任务录屏，放到 README 首屏。

完成门槛：80% 新用户不看文档完成，中位首次任务 ≤60 秒。

## 第 3 周：Windows 与插件作者

- 发布 Windows x64 签名候选版；
- 覆盖中文、空格、emoji 用户路径以及无管理员权限安装；
- 邀请 5–10 名插件作者使用模板和安装审查；
- 收集生命周期脚本、权限声明和兼容性痛点；
- 建立第一批精选插件候选清单，但不开放自动全量搜索。

完成门槛：Windows 核心旅程通过；至少 5 个真实插件完成 add/update/remove 回归。

## 第 4 周：留存与方向决策

- 回访前 3 周所有测试者，计算 D1/D7 与真实任务数；
- 复盘安装、启动、首次任务、崩溃和上游漂移；
- 用候补名单和只读原型验证跨设备查看/审批；
- 决定第一个主题版本：优先修复最大漏斗损失，不按竞品功能数量选择；
- 发布完整月报，包含失败数据和下月停止事项。

跨设备投入门槛：至少 20 名长任务用户进入候补名单，且只读原型中 ≥30% 每周使用两次以上。

## 每周公开输出

- 一个签名或明确标注预览状态的 Release；
- 一条真实兼容记录；
- 一个用户可感知变化的 GIF/视频；
- 安装与首次任务数据；
- 已知问题和下一周唯一主题。
